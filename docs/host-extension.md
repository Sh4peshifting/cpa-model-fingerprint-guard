# 最小宿主接口提案

适用于 CLIProxyAPI v8.1.2。现有插件构建独立运行。以下为接口提案，原版宿主没有这些端点。

## 在执行边界交付认证事件

在 `sdk/cliproxy/auth/conductor_execution.go` 抽取每次实际 executor 调用的生命周期。由宿主分配 Attempt ID，并携带实际 Auth ID、认证世代、请求及解析模型、协议、是否诊断、开始和结束时间。普通请求开始时调用同步准入判定，拒绝仅排除这个 Auth ID，继续现有候选流程。结束时先交付结构化上游错误，再允许进入下一轮选取。对流，在首字节之前的失败、`StreamChunk.Err` 以及转译前识别出的 HTTP 200 SSE 错误帧提供相同回调。只传匹配所需的有界错误字段，过滤宿主产生的错误和诊断流量。

保持插件候选排除作为快速路径。把同步准入作为真正的调度约束，复用到重试、绑定会话、WebSocket、流和 Home 执行入口。在插件就绪前暂缓受该插件保护的路径；同进程替换时先关闭旧实例调度，装载已持久化隔离，再恢复准入。

## 提供一次账号和模型锁定的诊断调用

参考 `Manager.VerifyInference` 的精确 Auth ID、认证世代检查、准备与传输流程，增加只供已注册插件调用的通用诊断 RPC。

- 输入包含 Auth ID、预期凭证版本、请求模型、协议、经大小限制的请求体、最大执行时间以及可取消的操作 ID。解析时要求恰好一个上游模型，对模型池、其他 executor 插件、路由重写或不受支持的执行路径显式拒绝。结果返回实际 Auth ID、上游模型及凭证和路由版本。三次挑战之间版本变化时，该轮作废。
- 发起诊断前检查人工停用、重新登录要求、凭证限额及模型限额。仅在宿主能确认当前限制属于本次 502/503 暂时冷却且隔离由调用者持有时，允许诊断绕过该项准入。调用独立于普通调度，不重试到其他模型或认证。
- 不执行普通业务的冷却清理、成功计数、使用量观测或异常回调。沿用凭证刷新同步机制，但刷新后版本变化须返回冲突或由插件重启整轮。让操作超时和卸载直接取消宿主上下文，覆盖连接建立和上游读写。

原始 `host.model.execute` 支持 `auth_id`，仍会走常规模型规划和冷却。不要调用 `host.routing.reset_cooldown` 来模拟诊断准入，后者改变宿主的路由状态。

## 验收条件

- A 的 503 到达同步钩子后，新业务只由 B 接收。诊断仍能单独使用 A，且 A 的原生冷却、配额和人工停用不被改写。
- HTTP 200 SSE 错误在模型翻译前可按实际认证归属。在重试、流式请求及 WebSocket 中，开始和结束事件成对出现。
- 模型池、凭证限额、管理员停用和过期诊断均有拒绝用例。卸载能取消正在进行的诊断。
